## Architecture decisions
1. **Separate service** (`nutrition-core`, port 8095, role `synqoria_nutrition_runtime`), not folded into `operations-core`: the existing
   service is a generic JSON-item store for M21/22/23/25/29/31/37; M26 needs relational constraints and a clinical safety gate.
   It copies the proven patterns (cell/facility GUCs + forced RLS, restricted non-owner role verified on every transaction,
   command idempotency, audit + outbox in the same transaction, JWT scope claims) and does not modify them.
2. **No second authority.** Patient identity, allergies and fasting are *projections* (`patient_context`, `allergy_snapshots`,
   `fasting_instructions`) written only by the `m26:clinical_feed` principal with monotonic `sourceVersion`. Missing allergy data is
   UNKNOWN, never "no allergies". M26 issues no patient identifiers.
3. **Clinical vs kitchen permissions** are disjoint (`Perm.CLINICAL_ONLY`); a unit test asserts kitchen role sets never include them.
4. **Independence** is enforced in the domain *and* by DB CHECKs: approver ≠ prescriber, dispatch approver ≠ planner/preparer,
   acknowledger ≠ deliverer, substitution decider ≠ proposer, incident resolver ≠ reporter.
5. **One time-of-use safety gate** (`Domain.evaluate`) runs at plan, release, prepare, dispatch approval, tray load, tray dispatch and
   delivery. Unknown/outdated/revoked/expired/contradictory diet, missing/stale (>24 h, configurable 1–72 h)/changed allergy data,
   allergen conflicts and overlapping fasting all block. A blocked delivery commits a hold + escalated incident and returns 409.
6. **Structural duplicate prevention**: unique live meal per patient/date/meal, one tray per meal, one live batch per ward/date/meal,
   one APPROVED and one pending order per patient (partial unique indexes).
7. **Immutability**: triggers forbid UPDATE/DELETE/TRUNCATE on `audit_events`, content edits of non-PRESCRIBED orders, deletion of
   orders, and changes to recorded delivery/acknowledgment evidence — even for the table owner. Runtime role has no DELETE anywhere.
8. **Lock order ORDER → MEAL → TRAY** everywhere (found and fixed a real deadlock between delivery and revoke via the race test).
9. Committed rejections (wrong patient, safety block) are stored in the idempotency record and replay identically.

## Security findings
* Fixed: lock-order deadlock (delivery vs revoke) — regression test `revokeRacingTheDeliveryGateNeverShipsRevokedDiet`.
* Cross-cell/facility: foreign actors get `404` (not `403`); raw SQL without/with wrong scope sees zero rows; forged inserts fail RLS (tested).
* Idempotency rows store the full JSON response (contains patient label/refs). Needs a retention/purge job and access review.
* The browser proxy reuses the *operations* hospital sign-in cookie/CSRF (no IAM change made). The access token's audience must include
  the nutrition audience, or a dedicated sign-in must be added by the identity owner.
* `m26:*` grants are trusted from the short-lived JWT claim (≤15 min). The workforce grant authority that issues them does not exist yet
  (the existing operations service also denies until that evidence exists).

## Remaining external integrations / production acceptance blockers
1. Upstream **identity, allergy and fasting authorities** must publish to the `/feed/*` operations (this PR *defines* the consumed contract;
   it has not been ratified by those owners). Verified-source evidence and event signing are not implemented.
2. Clinical review of vocabularies (diet categories, texture levels, restriction/allergen codes, nominal meal times, 24 h allergy freshness).
3. Outbox relay (`published_at` updater role + broker/consumer inbox) is not implemented.
4. Facility time zone (`SYNQORIA_NUTRITION_FACILITY_ZONE`) and meal times are nominal; kitchen item catalogue / recipes / stock deduction (M22) not integrated.
5. Web stack: repo is on Next 15.5.6 / React 19.1.1; target Next 16.4.5 / React 19.3.1 belongs to the web-owner PRs #23/#24 and was not touched.
6. Real OIDC issuer/audience, DBA-provisioned runtime role, backup/PITR rehearsal, penetration test, accessibility audit, clinical safety sign-off.
