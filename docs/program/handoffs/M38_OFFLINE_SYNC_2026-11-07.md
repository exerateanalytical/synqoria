## NOT verified / honest gaps
* **There is no real offline client.** The durable local queue lives on devices (mobile/PWA) which do not exist in this repository. This module is the server side: contracts, protocol, conflicts and ownership. Network-interruption behaviour is covered by idempotent replay, retry outcomes and cursor tests, not by a real flaky network.
* Accepted commands advance the record **head** (version/hash) and are dispatched through the outbox; no domain adapter consumes them yet, so clinical records themselves are not changed by this service. Owning domains must publish heads (`POST /heads`, `/heads/{id}/revisions`) and consume the events.
* Device authentication is the bound OIDC user plus a registered device record; hardware attestation, device encryption at rest and remote wipe are external requirements.
* Command payloads are stored as sent (≤ 16 KB). A data-minimisation and retention policy for them is needed before production.
* No outbox relay, no scheduler, no load test, no `next build`, no browser rendering, no accessibility audit, no dependency scan or SBOM.
* Java 27 lane is informational.

## Open integration dependencies
1. Owning clinical domains (P06/P07) must register heads for synchronisable record types and consume accepted-command events; operation contracts must be approved per operation by their owners.
2. P03 must issue the `m38:*` grants and separate maker/checker roles.
3. A device/mobile client that implements the envelope, sequence, expiry and cursor rules.
4. Governance sign-off of which operations may ever run offline (the default is: none; clinical-safety-gated operations are structurally excluded).
