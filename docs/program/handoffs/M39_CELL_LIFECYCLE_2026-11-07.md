## Verified locally (real runs)
* `mvn verify` (Temurin 25.0.5, Spring Boot 4.1.2): **21 tests, 0 failures** — 6 pure domain + 15 against real `postgres:18.6` (including concurrent duplicate tenant requests → one winner, concurrent route switches on one epoch → one winner).
* `python tests/test_m39_openapi_contract.py`: 32 operations in parity with the Spring routes.

* Defects found by the tests and fixed: a PL/pgSQL trigger referenced a column of another table (no short-circuit), two `varchar(10)` columns too short for `PROGRESSING`/`ROLLED_BACK`, mixed database and application clocks in health gates (now the application clock throughout).
* GitHub Actions results for the pushed head are recorded on the PR.

## NOT verified / honest gaps
* **No infrastructure executor exists.** Provisioning, deployment and data copy are performed by external executors; this service records their results and enforces the rules. The data copy, catch-up lag and digests are *reported evidence*, not measured here.
* The migration `FAILED` state and `failure_code` column are reserved; a failed verification is refused (nothing changes) rather than recorded as a failed migration.
* Signing uses a symmetric HMAC key from configuration (`SYNQORIA_FLEET_ROUTING_KEY`, ≥ 32 chars); key rotation, HSM/KMS and asymmetric signing are not implemented. Gateways must verify signatures and expiry (`Domain.verify` is the reference).
* Health observations arrive by API; there is no probe. Health freshness is 5 minutes.
* Tenant isolation inside the control plane relies on the `synqoria_tenant_scope` claim issued by P03 (not implemented here).
* No outbox relay, no scheduler, no load test, no `next build`, no browser rendering, no accessibility audit, no dependency scan or SBOM. Java 27 lane is informational.

## Open integration dependencies
