## Design decisions
1. **Unknown is never zero.** A metric value is `OK`, `INCOMPLETE` (some inputs unusable, counted in `unknown_count`), `SUPPRESSED` (group below the minimum size) or `NO_DATA`. A database CHECK (`no_fabricated_numbers`) forbids a number on `SUPPRESSED`/`NO_DATA` rows. The UI shows a word and an explanation, and charts draw gaps, never zeros.
2. **Small-cell protection.** Clinical and operational metrics must declare `min_cell ≥ 5` (CHECK). Groups below it are suppressed, and complementary suppression prevents recovering a hidden group by subtraction from a published total.
3. **Cross-facility aggregates stay inside one hospital cell.** A permissive RLS policy exposes only `state='OK'` rows to a session carrying the `m28:cell_aggregate_read` grant, and the service combines them only when at least 3 facilities contribute; no single facility is returned.
4. **Currency-aware money.** Sums are grouped by currency and never combined; the unique index includes currency. The browser formats with integer arithmetic only.
5. **Verified sources only.** Sources are registered by one person and verified by another. Events carry a source, idempotency key and `occurred_at`; invalid events are quarantined, never silently dropped, and late events are accepted and flagged. Source freshness (watermark vs allowed staleness) is shown beside every figure.
6. **Deterministic projections.** Metrics are computed from stored facts with a versioned, approved definition (maker-checker, immutable once approved by trigger). A rebuild reproduces identical values (digest compared in tests).
7. **Reports and exports.** Reports are approved definitions with a maximum period and a required permission. Runs are queued and processed in the background and read stored, already-protected values only. Exports are **CSV only** (PDF/XLSX are refused with `unsupported_format`), need approval by someone other than the requester, carry a watermark and SHA-256, expire, and every download is audited and re-verified against the fingerprint. Cells are defended against spreadsheet formula injection.
8. **Browser surface is deliberately small.** Ingestion, source management, rebuild, quarantine and metric/report authoring are service-to-service or administrative and are not reachable through the browser proxy allow-list (tested).
9. **P03 remains the identity/grant authority.** Grants come from the short-lived token claim (≤ 15 min, closed 20-permission vocabulary).

## NOT verified / honest gaps
* GitHub Actions results for the pushed head are recorded on the PR. The Java 27 lane is informational. Next 16.4.5 and a real `next build` were not run (dependency ownership of PRs #23/#24); screens were not rendered in a browser, and no responsive or screen-reader check was done.
* **No real upstream sources exist.** Ingestion is defined here with synthetic events; the clinical, scheduling and finance owners have not ratified the event contracts.
* No streaming or bulk ingestion path and no load test. The report-queue worker is exposed as an endpoint; there is no scheduler daemon. The outbox relay is not implemented.
* Reports read stored metric values only; there is no ad-hoc query builder. No PDF/XLSX output.
* The statistical-disclosure thresholds (`min_cell` 5, 3 facilities) are engineering defaults that governance must confirm.
* No dependency vulnerability scan or SBOM.

## Remaining external integration / production acceptance blockers
1. Source-owner ratification of event schemas and definitions for each metric; clinical and finance review of every metric definition.
2. P03/identity must issue the `m28:*` grants, including separation of makers and approvers.
3. Governance sign-off of disclosure thresholds, export purposes and retention (the idempotency table stores full responses).
4. Outbox relay, scheduler, monitoring and alerting on source staleness.
5. Accessibility audit, penetration test, backup/PITR rehearsal, real OIDC issuer and DBA-provisioned runtime role.
