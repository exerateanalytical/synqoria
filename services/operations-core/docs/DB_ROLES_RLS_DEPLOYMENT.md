# M21/M22/M23/M25/M29/M31/M37 — Database privilege and deployment gates

- Scope: one PostgreSQL database *per hospital cell*. The service does not share an administrative write DB across cells or infer a cell from unverified request headers.
- SQL draft: `db/migration/V001__seven_operations_cells.sql`. Separate migration owner is required. First provision a distinct `synqoria_operations_runtime` role with LOGIN, NOINHERIT, NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOREPLICATION and NOBYPASSRLS; provision the password using a secret vault, never in a migration.
- Migration objects are owned by DBA/migration principal, not the application. Run DDL once using an independently authorized process. `FORCE ROW LEVEL SECURITY` and `USING + WITH CHECK` must be present on six tables. The application login can only read/write business records and idempotency, append audit/outbox, and apply guarded stock balances; it cannot UPDATE/DELETE audit, outbox or stock movement history.
- Runtime transaction must set `synqoria.cell` and `synqoria.facility` with transaction-local PostgreSQL settings derived *exclusively* from issuer/audience/signature-validated JWT identity claims and an authoritative workforce grant lookup, not request JSON or headers. RLS settings are **necessary but not sufficient** for full deployment authorization. Gated live authority is still incomplete.
- Event writes, aggregate version update and idempotency completion must occur within one database transaction. Outbox consumption/ACK must be a separately least-privileged bounded worker; no outbox publisher is qualified by this migration.
- Medical stock M13 is intentionally excluded; M22 is non-medication/general stores. M25 patient handover requires separate clinical authorizations; M31 signatures require approved third-party signature evidence. Both remain denied until adapters exist.
- **Do not apply this schema to production or declare modules complete** until PostgreSQL16 disposable CI proof, reviewed migrations, Keycloak and workforce grant integration, and operational acceptance.
